# ポモドーロタイマー 実装機能一覧

**作成日**: 2026年2月24日  
**バージョン**: 1.0

---

## 📋 実装する必要のある機能一覧

### 🎯 1. コア機能（タイマーロジック）

#### 1.1 時間管理抽象化
- **Clockインターフェース** - システム時刻の抽象化
- **RealClock** - 本番環境用の実際のシステム時刻
- **MockClock** - テスト用の制御可能な時刻

#### 1.2 タイマー機能
- **タイマー開始** - カウントダウン開始
- **タイマー一時停止** - 現在の状態を保持して停止
- **タイマー再開** - 一時停止から再開
- **タイマーリセット** - 初期状態に戻す
- **残り時間計算** - リアルタイムで残り秒数を算出
- **進捗率計算** - 0.0～1.0の進捗度を算出
- **経過時間計算** - 開始からの経過秒数を算出
- **完了判定** - セッション完了を検知
- **時間フォーマット** - MM:SS形式で表示用文字列を生成

#### 1.3 状態管理
- **作業モード** - 25分の集中時間
- **休憩モード** - 5分の短休憩
- **長休憩モード** - 15分の長休憩（4セッション後）
- **停止状態** - タイマー未実行状態

### 📊 2. セッション・統計機能

#### 2.1 セッション記録
- **セッション完了記録** - 完了したセッションの記録
- **セッション履歴管理** - 本日のセッション履歴を保持
- **タイムスタンプ記録** - 各セッションの完了時刻

#### 2.2 統計計算
- **完了セッション数** - 本日完了したセッション数
- **累計集中時間** - 本日の総集中時間（秒単位）
- **時間表示変換** - 「X時間Y分」形式に変換
- **統計リセット** - 本日の統計をクリア

#### 2.3 データ永続化
- **Repositoryインターフェース** - 永続化層の抽象化
- **FileRepository** - JSON形式でファイルに保存
- **InMemoryRepository** - テスト用メモリ保存
- **データ保存** - 統計情報の保存
- **データ読み込み** - 統計情報の読み込み

### ⚙️ 3. 設定管理機能

#### 3.1 タイマー設定
- **作業時間設定** - 5～99分で設定可能
- **休憩時間設定** - 1～99分で設定可能
- **デフォルト値管理** - 作業25分、休憩5分
- **設定バリデーション** - 最小値・最大値チェック
- **設定リセット** - デフォルト設定に戻す

### 🌐 4. バックエンドAPI

#### 4.1 タイマーAPI
- **POST /api/timer/start** - タイマー開始
- **POST /api/timer/pause** - タイマー一時停止
- **POST /api/timer/resume** - タイマー再開
- **POST /api/timer/reset** - タイマーリセット
- **GET /api/timer/status** - タイマー状態取得（ポーリング用）

#### 4.2 セッションAPI
- **GET /api/session/today** - 本日の統計取得
- **POST /api/session/complete** - セッション完了記録
- **POST /api/session/reset-today** - 本日の統計リセット（確認必須）

#### 4.3 設定API（Phase 5）
- **GET /api/config** - 現在の設定取得
- **POST /api/config/update** - 設定更新

#### 4.4 サービス層
- **TimerService** - タイマーのビジネスロジック
- **SessionService** - セッション管理のビジネスロジック
- **依存性注入** - サービス→モデルへの依存注入

### 🎨 5. フロントエンド機能

#### 5.1 UI コンポーネント
- **タイマー表示** - MM:SS形式のデジタル時計
- **状態ラベル** - 「作業中」「休憩中」「停止中」の表示
- **サーキュラープログレスバー** - SVG/CSSでの円形進捗表示
- **開始ボタン** - タイマー開始/再開
- **一時停止ボタン** - タイマー一時停止（状態により表示切替）
- **リセットボタン** - タイマーリセット
- **セッション数表示** - 本日完了したセッション数
- **集中時間表示** - 本日の累計集中時間

#### 5.2 JavaScript機能
- **APIクライアント** - fetch APIのラッパー（api.js）
- **タイマー状態管理** - フロントエンド側の状態管理（timer.js）
- **進捗バー描画** - SVGの動的更新（progress.js）
- **ポーリングロジック** - 1秒ごとのステータス更新
- **イベントハンドラ** - ボタンクリックイベント処理（main.js）
- **統計更新** - セッション完了時の統計表示更新

#### 5.3 スタイリング
- **レスポンシブレイアウト** - モバイル対応
- **アニメーション** - ボタンホバー、進捗バー遷移
- **カラースキーム** - UIモックに基づく配色
- **タイポグラフィ** - 読みやすいフォント設定

### 🧪 6. テスト機能

#### 6.1 単体テスト
- **test_timer.py** - タイマーロジックのテスト（MockClock使用）
- **test_session.py** - セッション管理のテスト（InMemoryRepository使用）
- **test_timer_service.py** - タイマーサービスのテスト
- **test_session_service.py** - セッションサービスのテスト

#### 6.2 統合テスト
- **test_integration.py** - APIエンドポイントのテスト
- **エンドツーエンドテスト** - ブラウザでの動作確認

#### 6.3 テストインフラ
- **conftest.py** - pytestフィクスチャ定義
- **テストダブル** - MockClock、InMemoryRepositoryの実装
- **カバレッジ測定** - pytestのカバレッジプラグイン

### 📁 7. インフラ・設定

#### 7.1 プロジェクト構造
- **ディレクトリ作成** - models/, services/, routes/, static/, templates/, tests/
- **__init__.py** - Pythonパッケージ化
- **app.py** - Flaskアプリケーションエントリーポイント
- **config.py** - 設定ファイル

#### 7.2 データディレクトリ
- **data/** - セッション統計のJSON保存先
- **.gitignore** - データファイルを除外

## 🎯 実装の重要ポイント

### テスト駆動開発（TDD）
- 各機能の実装前に、まずテストを作成
- Mock/Stubを活用して依存関係を分離
- カバレッジ80%以上を目標

### 依存性注入
- Clock, Repositoryは抽象インターフェースに依存
- テスト時にMockを注入可能な設計
- サービス層での疎結合を維持

### 段階的実装
- Phase 1～2でMVP（最小限の動作版）を完成
- Phase 3～5で完全版を実現
- Phase 6～7で品質向上・機能拡張

### コード品質
- 型ヒント（Type Hints）の活用
- docstringによるドキュメンテーション
- PEP 8準拠のコーディングスタイル
